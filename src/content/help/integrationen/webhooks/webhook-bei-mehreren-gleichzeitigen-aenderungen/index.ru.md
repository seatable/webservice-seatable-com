Обычно SeaTable отправляет один webhook на каждое изменение строки. Однако если одна операция изменяет несколько строк одновременно, создаётся только один webhook с дополнительным параметром _row\_count_. Это относится и к API: один вызов API создаёт один webhook независимо от того, изменяет он одну строку или несколько.

В веб-редакторе это происходит, например, если вы копируете значение в буфер обмена с помощью {{< key "CTRL" >}}+{{< key "C" >}}, а затем вставляете его в несколько других строк с помощью {{< key "CTRL" >}}+{{< key "V" >}}. В этом случае создаётся только один webhook. На следующем рисунке показан соответствующий webhook.

![Несколько одновременных изменений через webhook.](images/webhook_multiple_changes.jpg)

## Что содержит webhook

Параметр _row\_count_ указывает количество затронутых строк. Остальные данные, такие как _row\_id_, _row\_name_ и _row\_data_, относятся только к одной строке, как правило, к первой строке операции. _op\_type_ также остаётся в единственном числе, то есть _insert\_row_, _modify\_row_ или _delete\_row_.

В настоящее время нет возможности создать отдельный webhook для каждой строки. Webhook также не содержит списка всех затронутых строк.

## Запрос изменённых строк после webhook

{{< warning headline="Webhooks не предназначены для синхронизации" text="Если вы хотите синхронизировать данные с другой системой, webhook должен быть только триггером для синхронизации. Он содержит не все изменения, и его доставка не гарантируется." />}}

После получения webhook запросите изменённые строки через [интерфейс SQL](https://developer.seatable.com/sql/select/):

```sql
SELECT * FROM Table1 WHERE _mtime >= '2026-11-05T18:30:00+01:00' ORDER BY _mtime, _id LIMIT 1000 OFFSET 0
```

Учитывайте следующие моменты:

- **Сравнение с помощью `>=`:** Столбец _\_mtime_ обычно имеет точность только до секунды. С `>` вы пропустите изменения, сделанные в ту же секунду, что и последняя синхронизация. Поскольку `>=` возвращает некоторые строки повторно, ваша система должна уметь обрабатывать дубликаты.
- **Указание часового пояса:** Время без часового пояса не интерпретируется как UTC. Поэтому всегда указывайте смещение, например `+01:00`.
- **Постраничное получение результатов:** Без `LIMIT` SQL-запрос возвращает не более 100 строк, а максимум на один запрос составляет 10 000 строк. Увеличивайте `OFFSET`, пока запрос не вернёт меньше строк, чем указано в `LIMIT`.
- **Удалённые строки и связи:** Удалённые строки не попадают в этот запрос, а добавление связи не изменяет _\_mtime_. Поэтому время от времени сравнивайте идентификаторы строк и столбцы связей в обеих системах.

## Дополнительная регулярная синхронизация

Webhooks не гарантируют полную доставку: неудачные доставки не повторяются, webhook может быть [отключён после ошибок]({{< relref "help/integrationen/webhooks/deaktivierung-eines-webhooks-bei-fehlern" >}}), а в отдельных случаях может не быть отправлен вовсе. Поэтому дополнительно запускайте синхронизацию по расписанию и регулярно проверяйте, активен ли webhook.
